📋 WHAT EACH STEP DOES

1
User Input — Customer states loan need via Streamlit or CLI
2
Safety Gate — Keyword filter + GPT-4o-mini classifier blocks off-topic; PII masked before any logging
3
Profile Collection — Planner drives next_question() sequence (income, tenure, amount, product)
4
ReAct Reasoning — GPT-4o agent runs Thought → Action → Observation loop to select tool(s)
5
Tool Execution — MCP or direct tools: eligibility, EMI, checklist, RAG policy, escalation
6
RAG Retrieval — query_loan_policy fetches relevant policy chunks from ChromaDB
7
Response Generation — Indicative rate range + EMI estimate + eligibility + checklist streamed to UI
8
Escalation (if ceiling breach) — generate_escalation_summary packages RM handoff automatically
9
Observability + RLHF — Langfuse traces run; user feedback updates adaptive_policy.json

✅ BENEFITS OF EACH LAYER

🛡️
Safety Layer — Two-stage gate prevents misuse; PII never logged raw
⚙️
MCP Layer — Standardised tool protocol; swappable to remote MCP service with no agent changes
📚
RAG Layer — Answers grounded in bank policy; eliminates hallucinated rates
🧠
Memory (k=10) — Maintains context without overloading the context window
📊
Langfuse — Full trace visibility; per-session score for RLHF feedback signal
🔄
RLHF — Adaptive policy file improves agent behaviour cross-session

🔑 KEY DESIGN DECISIONS

🔀
Dual tool path: FastMCP when mcp importable; direct @tool imports otherwise — identical 5-tool surface to agent
🤫
Silent auto-detect: core_agent probes import mcp before choosing path — no warnings, no crashes
📡
Langfuse only: LangSmith and Arize Phoenix excluded — single observability tool (see engineering_justification.md)
🌊
Streaming UI: agent.stream_response() + st.write_stream() for real-time token output to Streamlit
🔒
Never commit .env: all API keys via environment variables; PII masking before any log write
