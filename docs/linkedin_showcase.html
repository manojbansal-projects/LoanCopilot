What Makes it Different

Production-Grade Design Decisions

These aren't just notebook experiments. Each decision was made with real-world deployment constraints in mind.

⚙️

MCP: Swappable Tool Transport

The 5 tools are exposed via Model Context Protocol — when the mcp package is available, FastMCP handles tool calls. When absent (CI, system Python), it silently falls back to direct LangChain @tool imports. Same tool surface, zero manual configuration, zero warnings.

🛡️

Two-Stage Safety Guardrails

Stage A keyword filter runs at microsecond speed to catch obvious misuse. Stage B uses GPT-4o-mini as a low-cost intent classifier for nuanced cases. PII (Aadhaar, PAN, mobile) is regex-masked before any log write. No raw PII ever reaches storage.

🔄

Two-Layer RLHF

Layer 1 injects within-session feedback signals for immediate course correction. Layer 2 calls update_adaptive_policy() to persist learnings cross-session into adaptive_policy.json — the agent genuinely improves from real usage, not just one-shot tuning.

🔢

424-Test Suite

226 core tests covering all 5 tools + agent + safety + retrieval. 182 coverage tests for edge cases. 16 RLHF adaptive tests that verify the feedback loop actually changes agent behavior. pytest with conftest fixtures — no mock-the-database anti-patterns.

I Built an AI-Powered Loan Origination Copilot for My IIT Madras Capstone — Here's the Full Story

When a retail bank customer walks into a branch and asks "Can I get a ₹50 lakh home loan?", they typically wait 2–3 days just to get a basic eligibility answer. That delay happens not because the answer is complicated — it's because the knowledge lives in policy documents, spreadsheets, and the heads of relationship managers who aren't always available.

For my IIT Madras AI Program capstone, I set out to fix this with a conversational AI agent. Not a chatbot that deflects to "please visit your branch." A real AI copilot that gives an indicative eligibility assessment, an EMI estimate, a document checklist, and policy-grounded answers — in a single conversation, in under 30 seconds.

What the Copilot Does

The agent covers four loan products (Home, Personal, MSME, New Car Loan) and handles the full early-stage origination conversation through five purpose-built AI tools:

  • Eligibility Assessment — calculates Fixed Obligation to Income Ratio (FOIR), checks credit score thresholds, and validates amount and tenure against product-specific limits.
  • EMI Calculator — uses a reducing-balance formula with an indicative rate range. A hard constraint: it never gives a single promised rate — always a range (e.g., "8.50%–9.25% p.a.") with a disclaimer that the actual rate is confirmed at sanction.
  • Document Checklist — a product × employment-type lookup (salaried vs. self-employed, across all four products).
  • Policy FAQ via RAG — semantic search over a ChromaDB vector database built from synthetic policy documents. Answers are grounded in actual retrieved chunks, not hallucinated.
  • Auto-Escalation — when a customer's loan requirement exceeds the escalation ceiling (₹1.5 Cr for home loans, ₹2 Cr for MSME, etc.), the agent automatically generates a Relationship Manager handoff packet.

The Architecture: 7 Layers with Clear Boundaries

The system is built in seven layers — each with a specific responsibility and a clean interface to the layers above and below:

  • Interface Layer — Streamlit web UI (token-by-token streaming) + CLI + MCP Server endpoint for Claude Desktop.
  • Safety Layer — Two-stage guardrails: a fast keyword filter (Stage A) followed by a GPT-4o-mini intent classifier (Stage B). PII (Aadhaar numbers, PAN cards, mobile numbers) is regex-masked before any log write.
  • Agent Layer — LangChain AgentExecutor running a ReAct (Reason + Act) loop with GPT-4o. A conversation window memory (k=10) maintains context. A profile planner drives structured question collection.
  • MCP Layer — FastMCP server exposing all five tools via Model Context Protocol. Silent auto-detection: if the mcp package is importable, it uses the MCP path; otherwise it falls back to direct LangChain @tool imports with zero warnings and zero crashes.
  • Tool Layer — The five tools described above, each with its own module and unit tests.
  • RAG / Knowledge Layer — ChromaDB with persistent storage, OpenAI text-embedding-3-small embeddings, and an ingestion pipeline (loader → chunker → embedder → store → retriever).
  • Observability + RLHF — Langfuse (self-hosted) traces every agent run. A two-layer RLHF system: Layer 1 injects within-session feedback signals; Layer 2 persists learnings cross-session into adaptive_policy.json.

What Makes it Production-Grade

424 tests. 226 core tests covering all five tools, the agent, safety, and retrieval pipeline. 182 coverage tests for edge cases. 16 RLHF adaptive tests that verify the feedback loop actually changes agent behavior. I hit a wall early — mock-heavy tests were passing while real behavior was wrong. The fix was to test against real ChromaDB instances, not mocked ones. Painful lesson, worth internalizing.

MCP as a swappable transport. The Model Context Protocol layer means that if tomorrow you want these tools running as a remote microservice instead of an in-process FastMCP server, you change one line in the config. The agent doesn't know or care. This is the kind of boundary that makes systems actually maintainable.

Safety as Day 1 architecture. The two-stage guardrail (keyword filter + LLM classifier) and the PII masking regex are not afterthoughts — they were designed in Phase 1 and informed every subsequent decision. No raw PII ever reaches a log file. No response ever promises a rate. Every escalation ceiling breach triggers the handoff tool automatically. These constraints are enforced in code, not just in documentation.

The Biggest Lessons

RAG quality is dominated by chunking strategy, not model choice. Switching embedding models gave me marginal improvement. Fixing my chunking strategy to respect policy section boundaries gave me a 40%+ improvement in retrieval precision.

Observability from day one, not day nine. I integrated Langfuse in Phase 8. I should have done it in Phase 3. Having traces from the start would have cut debugging time in half.

MCP is worth learning now. Model Context Protocol is becoming the standard for how AI agents connect to tools. Building with it — even for a capstone project — gives you hands-on experience with what enterprise AI deployments will look like in 18 months.
